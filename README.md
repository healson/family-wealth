# 🏠 家庭财富管理（Family Wealth Manager）

部署在 NAS 上的家庭财富管理 Web 应用，单容器 Docker 部署，自适应 PC / 手机端。
多账号、数据隔离、**资金全链路强关联**、AI 分析、MCP 接口，一套系统管全家人的钱。

当前版本：**v1.9.0**

## 💸 资金强关联体系（v1.2+ 核心设计）

系统遵循**「家庭财富流动过程」**设计理念：**每一笔资金动作都落在账户余额上**，钱从哪个账户进、从哪个账户出，全程可追溯、可对账。

| 资金动作 | 现金账户余额 | 投资账户余额 | 应收/应付 | 说明 |
|---|---|---|---|---|
| 记收入（选账户） | **+** 金额 | | | 工资入账，选「日常收支 → 记一笔 → 收入」 |
| 记支出（选账户） | **−** 金额 | | | 消费扣款，选「日常收支 → 记一笔 → 支出」 |
| 存取（存入/取出） | + / − | | | 现金等特殊场景（外部进账请用记收入） |
| 转账 A→B | A **−** / B **+** | | | 账户间资金移动，不产生收支 |
| 借出给别人 | **−** 金额 | | 应收 + | 从发生账户出账 |
| 借入 | **+** 金额 | | 应付 + | 入发生账户 |
| 收回借款 | **+** 金额 | | 应收 − | 从收款账户入账 |
| 归还借款 | **−** 金额 | | 应付 − | 从出账账户扣款 |
| 保单缴费 | **−** 保费 | | | 从缴费账户出账，并留缴费记录 |
| 购入固定资产 | **−** 购价（全款部分 = 购入价 − 贷款余额） | | | 仅**自付部分**从付款账户出账；贷款由银行直接付给卖方、不经家庭账户，故不扣款 |
| 投资转入 | **−** 金额 | **+** 金额 | | 现金 → 投资 |
| 投资转出 | **+** 金额 | **−** 金额 | | 投资 → 现金 |

> **守恒等式**：现金账户合计 + 投资账户合计 + 固定资产净值 + 借出应收 = 借入应付 + 资产贷款 + 净资产。
> 任意操作后，总览「余额对账」卡片都会校验每个账户：**期初基准 + 全部资金流水 = 应有余额**，与实际余额对比，有差异即标红提示。

**要点**：
- **记一笔必须选择账户**（不选会提示）：收入自动加余额、支出自动减余额；修改金额/类型/账户、删除记录时余额自动回滚，不会错账。
- 所有联动均支持**反向回滚**：删除借款、**保单（退回已缴全部保费）**、资产、**投资账户（回滚其转入/转出）**、收支记录、转账，余额均恢复原状；**删除现金账户**会同步撤销其转账对**对方账户**的影响，并解除其余模块的账户关联。
- **固定资产只扣「自付部分」**：购入价 − 贷款余额。仅改估值或修改贷款余额**不会**重复扣减账户。
- 历史数据以**账户当前余额为基准**，从升级后新记的账开始强关联，不追溯调整旧流水。

### 方式二：从 GitHub Container Registry 直接拉取（免 NAS 构建，推荐 ⭐）

镜像由 GitHub Actions 在**每次 push main（或打 `v*.*.*` 标签）**时自动构建并推送到 `ghcr.io/healson/family-wealth`，NAS 上**无需 node / docker build 环境**，直接拉取运行：

```bash
# 1. 登录 GHCR（私有仓库必须登录；密码处用有 read:packages 权限的 PAT）
docker login ghcr.io -u healson
#   → 密码填 PAT（建议单独建一个只勾 read:packages 的令牌，比全权限 PAT 安全）

# 2. 拉取预构建镜像并启动（默认 docker-compose.yml 已指向 GHCR 镜像）
docker compose pull
docker compose up -d

# 3. 访问 http://NAS地址:8000
```

- **升级**：`docker compose pull && docker compose up -d` 即可拉到最新镜像（无需 --no-cache 重建）
  - ⚠️ `docker compose up -d` **本身不会拉新镜像**（本地已有就不再拉），必须带上 `pull`，否则会静默继续跑旧版本
  - 若 compose 里锁定的是版本号（如 `:1.8.0` 而非 `:stable`），升级时先把 `image:` 那行的版本号改掉，再 `pull && up -d`
  - 拿不准有没有新版本：App 里「设置管理 → 系统更新 → 检查更新」（只提示，不自动升级）
- **私有镜像可见性**：首次构建后到 GitHub → 个人头像 → **Packages → family-wealth → Settings** 确认可见性为 **Private**（与私有仓库一致；若显示 Public 请改为 Private）
- **想本地构建**（NAS 不能访问 GitHub / 想改源码现场构建）：用 `docker compose -f docker-compose.local.yml up -d --build`（本地构建版，对应原 tar.gz 部署流程）

> **镜像标签怎么选**（四个标签互不干扰，各自由 CI 的 `enable` 条件精确控制）：
>
> | 标签 | 由什么写入 | 含义 | 适合 |
> |---|---|---|---|
> | `:stable` | **只有打 `v*.*.*` 标签** | 最近一次正式发布 | **生产环境（compose 默认用它）** |
> | `:X.Y.Z` | **只有打 `v*.*.*` 标签** | 某一个具体版本，永不移动 | 固定版本 / 回滚 |
> | `:latest` | 只有 push main | 主干最新（已过测试门禁，但未走发布流程） | 尝鲜 |
> | `:sha-<短提交>` | 只有 push main | 按提交定位 | 精确回溯 |
>
> 发布新版本：`git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z` —— 这一步会同时产出 `:X.Y.Z` 与 `:stable`。
> **主干开发不会动 `:stable`**，所以「打标签」就是「把一个测试过的版本推进到生产」这个动作本身。
>
> ⚠️ 推 tag 时 `:latest` **不会**被改动（workflow 里用 `flavor: latest=${{ github.ref_type == 'branch' }}` 显式关掉了 tag 事件的 latest）；
> 但 tag 推送使用的是**该 tag 所在提交里的 workflow**，所以对旧提交补打的标签仍按当时的旧规则构建。
>
> 目前远端已打过 `v1.8.0` → 可用 `ghcr.io/healson/family-wealth:1.8.0`；更早的版本没有标签，若拉那些版本号会报 `manifest unknown`。
> 想锁定某次构建，也可直接按 digest 拉取：`ghcr.io/healson/family-wealth@sha256:<digest>`。

## 🔄 升级现有版本（旧版 → v1.6.2）

> 升级**不会丢失数据**：数据库在 `./data` 目录（宿主机映射），与容器镜像相互独立；
> 新版本启动时会**自动迁移旧库**（自动补列/建新表，含全部资金强关联列），无需手动操作。

### 第一步：备份数据（务必先做 ⚠️）

```bash

# 方法二：应用内导出（需登录后操作）
# 设置管理 → 数据管理 → 导出备份 → 下载 JSON
```

# 上传新版本压缩包并解压（可覆盖旧目录，或解压到新目录）

### 升级常见问题（FAQ）

| 现象 | 原因与解决 |
|---|---|
| 登录后数据全没了 | `./data` 没挂载对：检查 docker-compose.yml 的 volumes 映射路径，确认是旧数据目录 |
| 端口被占用启动失败 | 改 docker-compose.yml 的 `ports: "5888:8000"` 冒号左侧为新端口 |
| 构建报错 / 拉取失败 | 确认 Docker 版本较新（`docker version`），内网可先配置镜像加速 |
| 老版本（v1.4 及更早）升级后总览打不开 | 旧库自动迁移：启动时自动补**全部强关联列**（账户关联列、缴费日、期初基准等）与缴费/投资流水表，无需手动处理；升级包请务必 `--no-cache` 重建 |
| 想看演示数据 | 新库首次启动 `SEED_DEMO_DATA=true` 才写演示数据；升级库不会重复写入 |
| AI 助手提示未配置 | 页面「模型设置」配置，或 docker-compose.yml 加 `AI_API_KEY` 后重建 |

> ```

### 1️⃣ 首次登录与多账号
- 默认账号 `admin` / `admin123` 登录，**立即修改密码**（设置管理）
- 管理员在 **设置管理 → 账号管理** 中新增家庭成员账号（如"李女士"），并可随时修改其用户名/密码或删除
- 每个成员用自己的账号登录，数据互相隔离，各记各的账

### 2️⃣ 日常记账（强关联核心）
- **日常收支 → 记一笔**：类型（收入/支出）、金额、分类（下拉内可直接新增/删除分类）、**账户（必填）**、日期、备注
- **余额自动联动**：选「收入」账户余额 **+**；选「支出」账户余额 **−**；修改金额/类型/账户、删除记录都会自动回滚，余额始终与流水一致
- **预设分类**：首次使用自动生成默认收支分类（收入：工资/理财/奖金/其他；支出：餐饮/交通/居住/购物/医疗/教育/娱乐/人情往来/其他）
- **交易模板一键套用**：打开「记一笔」窗口，顶部「套用模板」下拉直接选择 → 类型/金额/分类/账户/备注自动预填，改日期保存即可

### 3️⃣ 现金账户与转账
- **账户列表**：每个账户显示当前余额；「资金流水」按钮查看该账户**全部**资金动作（收支/存取/转账/借款/保单/资产/投资），每笔带 +/- 与逐笔结余，**可删除误记的流水**（余额自动回滚；保单缴费为历史留痕不可删）
- **流水记录 / 流水日历 / 周期统计**：展示**全部现金账户**的全链路资金流水（含通过日常收支记账、转账、借贷、保单缴费、资产购入、投资进出产生的每一笔），流入/流出统计与总览「本月资金流向」口径一致
- **记账（存取）**：仅用于现金等特殊场景（外部进账请用「记一笔-收入」，账户间移动请用「转账」）
- **转账**：A → B，A 减、B 加，余额自动同步

### 4️⃣ 借款管理（借出/借入）
1. **新增借款**：类型选「借出」或「借入」，填写对方、金额，**选择发生账户** —— 借出自动从账户扣款、借入自动入账。**类型选错请删掉重新新增**：类型决定资金方向，属已发生的历史事实，编辑时不可修改（弹窗中该选项已置灰）；删除会逐笔回滚已登记的收款/还款与本金，账户精确复原，重新新增即可
2. 对方还钱/你还钱时：进入该借款 → 「收款/还款」登记金额，**选择入账/出账账户**，余额自动同步，剩余金额自动计算
3. 全部还清自动标记「已结清」；到期未还标⚠️逾期，并进入总览提醒
4. 结清状态由「本金 − 已收/已还」**自动派生**：改金额会立即重算（比如把 1 万的借款改成本该 1.5 万，会从「已结清」回到「未结清」并补扣 5000）；借款页封面与财富总览的应收/应付同源一致

### 5️⃣ 保单缴费闭环
1. 新增/编辑保单时**选择缴费账户**（保费从该账户支出）
2. 保单卡片点「**缴费**」→ 一键从缴费账户扣减本期保费、记录缴费日期，并按缴费方式**自动推进下次缴费日**（年缴+1年 / 半年缴+6月 / 季缴+3月 / 月缴+1月，自动处理月末与闰年）
3. 到期前提醒弹窗点「去处理」直达保单页；缴费记录留痕，可在账户「资金流水」中追溯每期缴费
4. **删除保单会退回该保单已缴的全部保费**（余额自动恢复）——避免钱已扣、流水却消失导致「余额对账」出现永久差异

### 6️⃣ 投资转入/转出
1. 新增/编辑投资账户时**设置关联现金账户**
2. 账户卡片点「**转入**」→ 现金账户减、投资账户加；「**转出**」→ 投资账户减、现金账户加，双向自动同步
3. 删除转入/转出流水自动回滚；日盈亏按「记盈亏」维护（盈利红、亏损绿）

### 7️⃣ 固定资产购入
1. 新增/编辑资产时**选择付款账户** → **自付部分（购入价 − 贷款余额）**自动从该账户支出；贷款部分由银行直付卖方、不经账户，故不扣款
2. 「估值」记录历史价值，资产价值趋势自动生成；贷款余额计入负债。**仅修改估值或贷款余额不会重复扣减账户**
3. **历史购置（钱早已付清）**：不要关联当前账户——编辑资产时**清空付款账户**保存即可，账户余额自动恢复（不扣款）；资产照常记录，净值=当前估值−贷款余额

### 8️⃣ 财富总览
- **三笔钱配置**（家庭总资产上方）：现金账户/投资账户按「资金用途」标签（应急/稳健/长期）自动汇总为三个占比环形图，附每笔钱的投资去向与收益参考；标签在「现金账户 / 金融投资」的新增/编辑账户表单中设置（现金默认应急、投资默认长期，可随时修改）
- **统计区**：家庭总资产 / 家庭净资产竖向并列 + 净资产构成饼图；下方收入 / 支出 / 盈余三卡
- **本月资金流向**：流入（收入/借入/收款/投资转出）vs 流出（支出/借出/还款/保单缴费/资产购入/投资转入）+ 净流向，一屏看清钱从哪来、到哪去
- **余额对账**：每个账户「应有余额 = 期初基准 + 全部资金流水」vs 实际余额，一致绿标、差异红标（手工改余额/漏记/重复记账会立刻暴露）
- 顶部右侧「最近一个月到期提醒」滚动显示保单缴费 + 借款还款

### 9️⃣ 支付账单导入
1. 在支付宝 / 微信支付等 App 导出账单 CSV（支付宝：设置→账单→导出；微信：钱包→账单→常见问题→下载账单）
2. 日常收支 → **📥 账单导入** Tab → 选择平台 → 上传文件
3. 预览解析结果（日期/收支/金额/自动匹配分类）→ 确认导入（**需指定账户，自动联动余额**）

### 🔟 交易模板与定时交易
- **交易模板**：日常收支 → 📋 交易模板 Tab → 新增（如"工资 25000 收入"）；记账时顶部「套用模板」一键预填
- **定时交易**：⏰ 定时交易 Tab → 每月第几天 / 每周星期几 / 每年月日 → 到点自动生成收支并**联动账户余额**；典型场景：每月 5 日工资、每月 20 日房贷、每年 1 月保费

### 1️⃣1️⃣ 附件与续期提醒
- **附件**：6 大模块新增/编辑均可上传图片、文档（合同/发票/凭证），列表内直接预览、下载、删除
- **续期提醒**：保单缴费/到期、借款还款到期前按规则自动弹窗；默认提前 1 个月/1 周/3 天/2 天/1 天各提醒一次，规则可在 **设置管理 → 提醒管理** 中增删改、启停

### 1️⃣2️⃣ AI 助手与数据管理
- **AI 助手**：顶部按钮进入 → 未配置时点「⚙ 模型设置」选择服务商/模型、填入 Key → 可问"我这个月花了多少钱？""哪些保单快到期了？""分析我的支出结构"
- **数据备份/恢复**：设置管理 → 数据管理 → 导出备份（JSON 全量）/ 导入恢复；或直接复制宿主机 `./data/family_wealth.db`
- **清空记录**：只清空收支/借款/资产等业务记录，**自动保留全部分类信息**（内置 + 自定义）

### 1️⃣3️⃣ 系统健康、回收站与自动备份（v1.9.0）
- **系统健康**：设置管理 → 「系统健康」。三张提示卡分别对应「账目是否平」「数据版本是否匹配」「备份是否可用」，右上角「重新检查」可立即重算。
  - **账目不平不是服务故障**：它不影响你继续记账，只是提醒你去「财富总览 → 余额对账」看看哪笔对不上（常见原因是手工改过余额、或漏记一笔）。**服务本身照常运行** —— 这一点是刻意设计的，`/api/health` 的状态码永远 200，业务状态只放在返回体字段里。
  - **数据版本不匹配**：只在「用旧镜像挂在新数据库上」时出现。此时界面会给出说明与建议（换回新镜像 / 先导出备份）。应用仍可启动使用 —— 自托管场景下可用性优先。
- **回收站**：设置管理 → 「最近删除」。支持按类型筛选、导出为 JSON。导出的每条都含被删记录的**完整字段**与**补充说明**（比如删保单时退回了多少保费、删账户时余额是多少），按需手工重新录入即可。
  - 刻意**不做「一键还原」**：被删记录与父记录的关联已不存在，自动重建容易把账搞乱；归档表也**不参与任何账目与对账**，所以删东西不会让余额变化。
  - 两处删除不归档：删除账号本身、以及启动时的重复提醒规则清理（都不是用户数据丢失）。
- **自动备份**：每天自动写一份（含全部账号），命名 `fw-backup-YYYYMMDD-HHMMSS.json`，轮转保留最近 `BACKUP_KEEP` 份，可点「立即备份」手动触发（建议升级前点一次）。
  - 备份文件形状与「导出备份」**完全一致**，因此可以直接拿去「导入恢复」—— 导入接口会自动识别备份文件并挑出当前账号的数据。
  - 🔴 **务必把 `BACKUP_DIR` 指到数据库之外的目录**（见上面「配置项」）。默认的 `./data/backups` 与数据库同卷，卷坏时两者一起没，等于没备份。界面上会就此给出醒目提示。

## 🎯 使用案例（场景化教程）

### 案例 1️⃣ 发工资了：记一笔收入
1. 日常收支 → 记一笔 → 类型选**收入**、金额 25000、分类「工资收入」、**账户选「工资卡」**、日期今天
2. 保存后：**工资卡余额自动 +25000**；本月资金流向「流入-收入」增加 25000
> 想省事？把工资存成交易模板，下月直接套用改日期。

### 案例 2️⃣ 日常消费：记一笔支出
1. 日常收支 → 记一笔 → 类型选**支出**、金额 320、分类「餐饮」、**账户选「工资卡」**、备注"周末聚餐"
2. 保存后：**工资卡余额自动 −320**，支出分类统计同步更新
> 小技巧：分类下拉底部可直接输入新分类回车添加；误加的分类点选项右侧 🗑 删除。

### 案例 3️⃣ 借给朋友 5000 元：完整的借出→收款闭环
1. 借款管理 → 新增借款 → 类型**借出**、对方"张三"、金额 5000、**账户选「工资卡」** → 保存后**工资卡余额 −5000**，总览「借出应收款」+5000
2. 一个月后张三还了 3000：借款记录点「收款」→ 金额 3000、**账户选「工资卡」** → **余额 +3000**，剩余自动变 2000
3. 再还 2000 结清 → 借款自动标记「已结清」，应收款归零
> 全程余额、应收、结清状态自动联动，不用手工对账。

### 案例 4️⃣ 给家人买保险：缴费闭环
1. 保单管理 → 新增保单 → 产品"国寿福"、保费 8500、缴费方式**年缴**、**缴费账户选「工资卡」** → 保存（此时**不扣款**）
2. 到缴费日（或提醒弹窗点「去处理」）→ 保单卡片点「**缴费**」→ **工资卡余额 −8500**，下次缴费日**自动推进到下一年**，缴费记录留痕
3. 明年到期前系统提前 1 个月/1 周/3 天/2 天/1 天弹窗提醒，再点一次缴费即可

### 案例 5️⃣ 把 3 万闲钱转入股票账户
1. 金融投资 → 新增投资账户"XX证券"，**关联现金账户选「工资卡」**（或在编辑中设置）
2. 账户卡片点「**转入**」→ 金额 30000 → **工资卡 −30000、股票账户 +30000**，两处余额同时变化
3. 行情不好想撤出 1 万 → 点「**转出**」→ 金额 10000 → 反向同步
> 日盈亏单独「记盈亏」：盈利填正数（红）、亏损填负数（绿），总览金融盈亏趋势自动汇总。

### 案例 6️⃣ 购置固定资产：买车
1. 固定资产 → 新增资产"家用轿车"、购入价 16 万、**付款账户选「工资卡」**、贷款余额 8 万
2. 保存后：**工资卡余额 −8 万**（全款部分），负债 +8 万；总资产按当前估值计算
3. 每年「估值」更新一次车价，固定资产趋势图自动更新

### 案例 7️⃣ 月底对账：看懂余额为什么变
1. 打开**财富总览 → 余额对账**卡片：每个账户显示「应有余额 vs 实际余额」
2. 全部「一致」→ 账平了 ✅；某个账户出现红色差异 → 说明有笔账没对上
3. 点进该账户 →「**资金流水**」逐笔核对（收支/转账/借款/缴费/资产/投资全在其中），找到漏记或重复记账的那笔，修正后差异自动消失

### 案例 8️⃣ 夫妻分工记账：多账号各记各的
1. 设置管理 → 账号管理 → 新增"李女士"账号
2. 丈夫记工资、房贷（自己的账号），妻子记日常开销、保单（她的账号）
3. 两人数据互不可见，但各自的总览、对账、提醒完整独立；管理员（admin）可随时修改/重置任一成员密码

### 案例 9️⃣ 每月 5 日自动记工资：定时交易
1. 日常收支 → ⏰ 定时交易 → 新建：名称"每月工资"、类型收入、金额 25000、分类「工资收入」、**账户选「工资卡」**、频率**每月第 5 日**
2. 之后每月 5 日系统**自动生成一笔收入并自动 +25000 余额**，备注带 ⏰ 标识
3. 房贷同理设每月 20 日支出；不想自动记账时随时停用

### 案例 🔟 用 AI 助手做月度复盘
1. 顶部「AI 助手」→ 模型设置里选 DeepSeek / Ollama 并填 Key
2. 对话示例："分析我这个月的支出结构""下个月有哪些保单和借款要到期""我的钱主要流向了哪里"
> AI 会基于你账号的实时数据回答，不泄露给其他账号。

## 📱 安卓 App（APK）打包

本项目前端为 React（Vite），已集成 **Capacitor**，可一键打包成安卓 APK（应用壳，界面与 Web 完全一致）。

### 方式零：直接下载已构建的安装包（最省事）

**不想自己搭 Android 构建环境**，到 [Releases 页面](https://github.com/healson/family-wealth/releases) 取最新版本的附件：

```
family-wealth-app-vX.Y.Z.apk
```

下载后覆盖安装即可（同包名 `com.family.wealth` 同签名，保留数据）。哈希校验、包信息、发布流程见 [`apk/README.md`](./apk/README.md)。

> ⚠️ 仓库是**私有**的，下载前需在浏览器里登录 GitHub（手机也要登录），否则点链接会 403。
> 📦 **v1.8.0 起 APK 不再提交进 git**：二进制进 git 后不可回收、每版约 +12.6 MB，
> 改为走 Release 附件（不进 git 对象库、可替换、有稳定直链）。v1.7.9 的包仍在 git 历史里，
> 取回方式见 [`apk/README.md`](./apk/README.md)。

### 方式一：一键脚本（需 JDK 21 + Android SDK）

```bash
cd frontend
# 指定你的 NAS 后端地址（家庭财富 API），然后执行
NAS_URL=http://192.168.1.100:8000/api ./build-apk.sh
# 产物（带版本号，自动复制到 frontend 目录）：family-wealth-app-vX.Y.Z.apk
```

- 首次执行会自动构建前端（注入 NAS API 地址）→ 同步资源 → Gradle 打包
- 无环境时：安装 [Android Studio](https://developer.android.com/studio)（自带 JDK/SDK）后即可运行
- **APK 命名带版本号**：脚本自动从 `backend/app/main.py` 的 `VERSION` 读取版本号，产物命名为 `family-wealth-app-vX.Y.Z.apk`，方便区分安装版本（与部署包 `family-wealth.tar.gz` 固定名不同）
- **系统「应用信息」里的版本号同源**：`android/app/build.gradle` 也在构建时读取同一个 `VERSION`，写入安卓的 `versionName`（如 `1.8.0`）与 `versionCode`（`X*10000+Y*100+Z`，如 `1.8.0 → 10800`）。此前这两项写死为 `1.0` / `1`，装了新版系统里仍显示 1.0；现在只要改了 `backend/app/main.py` 的 `VERSION`，APK 文件名与系统显示的版本一起跟随，无需手工同步。
- Windows 提示：`cap sync` 偶发失败（清理插件文件报错）时脚本会自动回退为手动同步 web 资源，不影响打包
- **体积保护（v1.8.0 起，APK 从 12.55 MB 降到 4.84 MB）**：两个独立原因造成过体积虚高，脚本都已处理 ——
  1. `android/app/src/main/assets/` 下的**全部内容**都会被 AAPT 原样打进 APK（不看你用不用，`mergeDebugAssets/merger.xml` 里可见）。历史上（2026-08-25 ~ 08-30）多次同步在该目录留下 6 份 `public_old_<时间戳>` 备份（磁盘 21.4 MB），而当前真正需要的 web 资源只有 2.5 MB。脚本现在会在打包前清掉该目录下除 `public` 以外的一切，**清不掉就中止**。
  2. AGP 的**增量打包**会把上一版里已删除的条目保留在原偏移、写成零长度占位，在新 APK 里留下大段零字节 —— 实测清掉备份后包内真实内容只剩 4.76 MB，文件却仍有 12.54 MB（其中 7.71 MB 是零填充）。脚本现在会在打包前 `rm -rf app/build/outputs` 强制重写。
  打包后还会用 JDK 自带的 `jar` 列一遍包内条目，发现 `_old_` 残留即中止。版本号解析也从 `grep -oP` 换成 `sed`（Windows Git Bash 不一定有 PCRE），**解析失败直接中止**而不是回退到写死的旧版本号。

### 🧪 回归测试与结构校验（资金守恒不变量 + 接口契约 + 部署契约）

> **v1.8.0 起这些检查是 CI 的构建门禁**：`.github/workflows/build.yml` 分 `test` 与
> `build-and-push` 两段，后者 `needs: test` —— **测试不过就不产出镜像**。
> 因此 `:latest` 与 `:stable` 都保证是「测试通过」的产物。

#### 一、后端行为回归（`backend/tests/`，八条自检脚本，共 348 项）

**不依赖真实数据**（各自使用临时库，跑完即清理），改完代码后跑一遍可确认没有破坏资金守恒、也没破坏接口出参类型：

```bash
cd backend
python tests/test_balance_audit.py      # 61 项：收支/转账/借款/保单/资产/投资/定时/导入/MCP 全链路余额联动与回滚
python tests/test_flow_registry.py      # 61 项：资金动作口径注册表守门（新表漏登记即 FAIL）
python tests/test_api_smoke.py          # 55 项：演示数据下全量读接口巡检 + 写接口返回体金额类型巡检
python tests/test_runtime_selfcheck.py  # 62 项：schema 哨兵 / 运行时对账 / 删除归档 / 自动备份
python tests/test_system_update_check.py # 46 项：更新检查接口（有更新/无更新/坏清单/不可达/令牌不泄露/缓存）
python tests/test_loan_status.py        # 32 项：借款「类型不可改」+ 结清状态同源派生 + 两处口径一致
python tests/test_loan_api_contract.py  # 22 项：借款列表排序（未结清在前）+ payments[].amount 必须是数字
python tests/test_migrations.py         #  9 项：模拟旧库升级，验证新增列能幂等补列并按父记录回填
python tests/probe_loan_edit_type.py    # 行为探针（非断言）：打印借款编辑的真实行为，供人工核对
```

`test_balance_audit.py` 的核心断言是**「余额对账」所有账户差异必须为 0**（即 `期初基准 + 全部资金流水 = 实际余额`），任何一处漏回滚、重复扣减或口径不一致都会让它失败。新增涉及余额的功能后，建议同步补一条用例。

`test_loan_status.py` 则守住另一类不变量：**服务端派生字段不接受外部写入**（改类型 / 写 `status` / 传未知字段一律 422），且**借款页与财富总览的应收应付必须同源一致**。

`test_loan_api_contract.py` / `test_api_smoke.py` 守的是**出参类型契约**：响应里的金额字段一律是 JSON 数字（递归扫描，不得出现 `"amount":"50.00"` 这种字符串），且全程不得出现 Pydantic serializer warning —— `Numeric` 列的 Decimal 一旦绕过 `float` 声明就是这个征兆，前端排序/求和与 MCP、AI 读取都会受影响。新增出参模型后建议跑一遍。

`test_runtime_selfcheck.py` 守三条**运行时**关键契约（都用 `with TestClient(app)` 让 lifespan 真正跑起来）：账不平 / 数据版本不匹配 / 备份损坏时，`/api/health` **都必须仍然是 200**（业务状态走字段，不走状态码）；以及「删除后账仍然平」证明回收站没污染资金守恒。

`test_flow_registry.py` 扫 SQLAlchemy metadata 守门：凡持有账户列的表，必须在 `utils.FLOW_SOURCES` 或 `utils.FLOW_EXEMPT_TABLES`（需写明理由）里，且登记来源必须真的在 `collect_account_flows` 里取数。**新增资金动作模型却忘了登记口径，CI 会直接拦下来。**

#### 二、结构校验（`check/`，三条脚本，CI 与本地同一份）

守的是「配置与产物」而不是运行时行为 —— 这类问题跑测试测不出来，但一改注释、一换 services 段就可能踩：

```bash
python check/check_version.py     # 17 项：版本号单一事实源链路（main.py → README「当前」→ 安卓读取而非写死 → apk 文件名）
python check/check_compose.py     # 54 项：三份 compose 的部署契约不变量
python check/check_tar.py         # 32 项：打包配方 = 打包校验（同一份排除规则）
python check/check_tar.py --out ../family-wealth.tar.gz   # 顺带产出交付包
```

- `check_compose.py` 额外校验**仓库内两份 compose 的凭据必须是占位值**，防止真实密码/密钥被误提交；也支持传入仓库外的副本路径（如 NAS 上那份含真实密码的）一起检查。
- `check_tar.py` 把「打包」与「校验」合到一起，避免「按 A 规则打包、按 B 规则检查」的假通过；历史上被它挡掉的坑（`.git` 未排除导致包体翻倍、安卓产物通配路径写错导致打进去 7 份构建产物）都写在脚本头部注释里。

## ⚠️ 安全提示

1. 首次登录后立即修改默认密码
2. 修改 `JWT_SECRET` 为随机值
3. 财务数据敏感，如暴露公网请务必配合 HTTPS 反向代理（Nginx/Caddy）+ 防火墙
4. 家庭内网远程访问建议使用 VPN（如 WireGuard / Tailscale）
5. 多账号场景请为每个成员设置独立密码
